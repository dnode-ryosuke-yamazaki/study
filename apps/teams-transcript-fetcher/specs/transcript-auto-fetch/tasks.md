# Teams録画トランスクリプトの自動取得 — タスク分解

> TDDで進める。各タスクは 🔴 Red(失敗するテストを書く) → 🟢 Green(最小実装) → 🔵 Refactor の順で進める。

対応する仕様: [requirements.md](requirements.md) / [design.md](design.md)

テストは標準ライブラリの `unittest` で書き、`python3 -m unittest` で実行する。HTTPアクセスは `urllib.request` を使う。**外部ライブラリは実行用・開発用ともに追加しない**(判断の根拠は [design.md#外部ライブラリの方針](design.md#外部ライブラリの方針))。

ファイルシステムを触るテストは一時ディレクトリを使い、**同期フォルダの実物には触らない**。HTTPアクセスを伴うテストは実際の通信を行わず、応答を差し替える。

### T13. 使用するURLの一覧の決定

**対象**: `fetch_transcripts.py`

**T14より先に実装する。** 既知のトランスクリプト件数の正は台帳ではなく「使用する一覧」であり、この決定が済むまで未取得の判定ができない。

4つの分岐すべてにテストを対応させる。

- テスト: **台帳にURLがなく、URLファイルがある場合、URLファイルの一覧が使われること**(フェーズ2の主経路。台帳側に比較対象の発行時刻がない状態で正しく選ばれること)
- テスト: 台帳にURLがあり、URLファイルもある場合、発行時刻が新しい方の一覧が使われること
- テスト: 台帳にURLがあり、URLファイルがない場合、台帳内の一覧が使われること
- テスト: どちらにもURLがない場合に「要発行」と判定されること
- テスト: **選んだ一覧の件数が「既知のトランスクリプト件数」となること。台帳が1件でURLファイルが2件の場合、既知件数が2になること**
- テスト: **選んだ一覧の件数が、これまでに観測した既知件数の最大値を下回る場合、最大値が既知件数として使われること**(URLファイルが古い内容に上書きされたケースで全件保存済みと誤判定しない)
- テスト: **観測した既知件数の最大値が状態に保持・更新されること**
- テスト: **選んだ一覧のURLの数が既知件数に足りない場合、足りない分が「要発行」と判定されること**(design 手順7)
- テスト: 発行時刻からの経過が期限しきい値を超えている場合に「要発行」と判定されること
- テスト: **期限しきい値を超えたと判定した場合、そのURLファイルが削除されること**
- テスト: **選んだ一覧の発行時刻が「恒久的失敗と判定した発行時刻の集合」に含まれる場合、アクセスを試みず「要発行」と判定されること**(同じURLを再試行しない)
- テスト: **集合に2つ以上の発行時刻がある場合、そのいずれと一致しても「要発行」と判定されること**(台帳のURLと再発行されたURLの両方が死んでいるケース)
- テスト: 発行時刻がUTC・ミリ秒までのISO 8601として解釈されること
- テスト: **フェーズ1では「要発行」の対象が記録に残されて終端となること**(発行要求は出さない)
- 仕様: [design.md#台帳の読み取りと使用するurlの一覧の決定バッチ](design.md#台帳の読み取りと使用するurlの一覧の決定バッチ) / [requirements.md#トランスクリプトの列挙](requirements.md#トランスクリプトの列挙) [1] [5] / [requirements.md#エラー時の挙動](requirements.md#エラー時の挙動) [1] [3]

## 検証項目の扱い

| 検証項目 | 観測する仕組み | 観測結果で調整するタスク |
|---|---|---|
| #1 ダウンロードURLの寿命 | T20のログ(URL発行からの経過時間) | T13の期限しきい値。期限切れが繰り返される場合は起動間隔の短縮(T21) |
| #2 一覧の応答項目 | T20のログ(台帳に含まれていた項目名) | T2・T7の識別方式。一意な識別子がなくても動く方式を既定にしてあるため、調整は任意 |
| #8 一覧から消えないか | T20のログ(同一録画の**選んだ一覧のURLの数**の推移)。既知件数は下限で固定されるため観測に使えない | 崩れていた場合、既知件数の下限(列挙[5])の扱いを見直す(T13)。暫定の打ち切りはT27で用意済み |

| #3 フローの改造方法 | T22の実施そのもの | 通らない場合はUI操作の手順書に切り替える |
| #10 識別子がファイル名に使える形式か | T22の実施そのもの(フロー①が台帳を作成できるか) | 満たさない場合、[design.md#識別子とファイル名の規則唯一の定義](design.md#識別子とファイル名の規則唯一の定義)に単純な置換規則を追加し、T2に反映する |
