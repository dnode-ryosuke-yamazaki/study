# 定型業務の週次レポート タスク

タスク 16件(claude 16 / copilot 0)

> TDDで進める。各タスクは 🔴 Red(失敗するテストを書く) → 🟢 Green(最小実装) → 🔵 Refactor の順で進める。

全件を claude 担当にした理由: 委任用アカウントのクレジット残量の記録が、月次リセット日(2026-10-01)を過ぎて無効になっている(リセット日到達)。

操作の記録(activity-recording)のタスク12(記録を期間で読む共通の処理)が終わってから着手する。このspecのタスク12は、activity-recording のタスク13〜15(操作スクリプト control.py と記録の操作Skill の SKILL.md を作る)が終わってから着手する。このspecのタスク9は、activity-recording のタスク14(共有の fixture `tests/fixtures/exclusion_request.txt` を作る)が終わってから着手する。このspecのタスク16は、activity-recording のタスク14・15(記録しないものを足す操作スクリプトと記録の操作Skill)が終わってから着手する。置き場所は、特に書かない限り `apps/routine-work-finder/application/` の下(以下このフォルダからの相対パス)。テストはこのフォルダで `python3 -m unittest discover -s tests -t .`、性能テストは `tests/perf/` を別に回す。

- `remake` は、週の指定が無ければ先に対象の週(金曜17時(日本時間)を過ぎた最新の週)を決め、そのあとで依頼のフォルダやデータフォルダに書けるかを確かめる。書けない(`Operation not permitted` など)ときは、何も書かずに `dataFolderUnwritable` で返し、結果の `data.week` に決めた週を入れる。Skill は手元のターミナル向けのコマンドブロック(`cd` と `remake --week <data.week の値>`)を渡し、自分で週を計算しない
- `remake --week` は `YYYY-Www`・`current`・`previous`・`last` を受け、日本時間で週を決める(時刻帯は Asia/Tokyo を明示し、時刻帯のデータが読めないときは固定の+09:00)。指定なしは `last` と同じ。依頼ファイルの `week` には決めた `YYYY-Www` を、`requestedAt` は+09:00付きで書く

- テスト: 作り直し-8・-9 の Skill 側は単体で確かめられないためタスク16で確かめ、操作スクリプト側は -2(決まった語での週の決め方)・-3(形の違う値を `invalidWeek` で断る)で兼ねる。-2(指定なしと `last` で金曜17時を過ぎた最新の週になる。`previous` は今の週の1つ前の週、`current` は今の週。金曜16:59・17:00・土曜で `previous` と `last` の違い。実行環境の時刻帯が UTC でも、時刻帯のデータが読めなくても日本時間で同じ週)、-3(月曜が27日前・28日前は受け付ける、29日前は `recordsPurged`。28日以内で記録のファイルが1つも無い週・まだ記録が無い今の週・まだ来ていない週は `noRecordsForWeek`。存在しない週と形の違う値(`今週`・`2026-41`・空)は `invalidWeek`。依頼のフォルダに書けないときは `dataFolderUnwritable` で何も書かず、週の指定が無いときも含めて `data.week` に対象の週が入る(書き込みを拒否する偽物に差し替える))、-4 のうち今の週を依頼できる
