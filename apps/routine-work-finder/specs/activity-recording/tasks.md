# 操作の記録 タスク

タスク 18件(claude 18 / copilot 0)

> TDDで進める。各タスクは 🔴 Red(失敗するテストを書く) → 🟢 Green(最小実装) → 🔵 Refactor の順で進める。

全件を claude 担当にした理由: 委任用アカウントのクレジット残量の記録が、月次リセット日(2026-10-01)を過ぎて無効になっている(リセット日到達)。

置き場所は、特に書かない限り `apps/routine-work-finder/application/` の下(以下このフォルダからの相対パス)。記録係のテストは `recorder/` で `swift test`、操作スクリプトのテストはこのフォルダで `python3 -m unittest discover -s tests -t .` で回す。`~/.claude/skills/` は Bash から書けないため、Skill のファイルは Write/Edit ツールで書く。

許可の付け直しが要るかどうかで、作り直しの運用と README の手順が変わるため、本体を作る前に確かめる。

## 記録係の判定と行の組み立て

### 2. 記録係の Swift パッケージを作り、設定ファイルを読んで記録するかどうかを決める処理を作る 【担当: claude】

終わりの日時を過ぎたら記録を止め、設定が読めなければ記録しない側に倒せるようにする。

<details><summary>詳細を開く</summary>

- `recorder/Package.swift`(外部の依存なし)、`Sources/RecorderCore/Config.swift`・`RecordingDecision.swift`
- 設定ファイルの形は appendix.md「設定ファイルの形」。必須項目の欠け・型違い・壊れた JSON は「設定が読めない」になる
- 判定: 終わりの日時なし・今がその日時以降は停止。直前の回の状態から、開始・停止の行を書くべきかと停止の理由を返す
- テスト: 記録の始め方・止め方-4(1秒前・ちょうど・後、停止の行が1回だけ)、-5、記録の始め方・止め方-1 の契約(タスク11が書き出すファイルを fixture にし、欠け・型違い・壊れた JSON の失敗形3つ)

</details>

### 5. 記録係が1行分の記録・本文・開始と停止の印を日ごとのファイルに書き足す処理を作る 【担当: claude】

- テストが書き出した行を `tests/fixtures/recorder_lines/` に保存し、タスク12の契約テストの fixture にする
