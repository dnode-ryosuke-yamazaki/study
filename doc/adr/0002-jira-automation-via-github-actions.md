# 0002. GitHub ActionsによるJIRAチケット自動更新

## ステータス

Accepted (2026-08-05)

## コンテキスト

これまでJIRAチケットへのコメント追加・ステータス更新は人手で行っていた。実装を進めるたびに手作業で状況を転記する負荷を減らすため、PRの作成・更新・マージといったgitイベントに連動してJIRAチケットへ自動でコメント追加・ステータス遷移を行いたい。

トリガー層としてはClaude Code hooks（対話セッション内でのみ発火し、他エンジニアの変更やセッション外の変更を拾えない）とGitHub Actions（実際のgitイベントに連動し誰の変更でも一律に動く）の2案があり、後者を採用する。

また、このリポジトリのブランチ命名は現状 `feature/<機能名>`（日本語の機能名ベース）であり、JIRAチケットキーを含んでいない。自動化にはチケットキーとgit上の作業の紐付け方式が必要。

## 決定

- **トリガー**: GitHub Actionsの`pull_request`イベントを使う。「PR作成/更新時」（`opened`/`synchronize`）でコメント追記、「PRマージ時」（`closed`かつ`merged == true`）でステータス遷移を行う
- **チケットキーの紐付け**: ブランチ名にJIRAキーを含める方式（`feature/<JIRAキー>-<機能名>`、例: `feature/NMBM-123-add-login`）を採用する。CI側は正規表現でブランチ名からキーを抽出する。これに伴い`.claude/skills/pr/SKILL.md`のブランチ命名規約を更新する
- **自動化の範囲・安全策**: コメント追記・ステータス遷移とも自動化するが、JIRA更新ジョブはCIの必須チェック（マージのブロッカー）にしない。ベストエフォートの副作用として設計し、以下を満たす:
  - ステータス遷移は名前推測ではなく、対象チケットの現在有効な遷移一覧をJIRA APIから取得したうえで解決する（人間が既に別ステータスへ動かしていた場合など、想定した遷移が存在しないケースを許容する）
  - 遷移が解決できない場合はステータス変更をスキップし、コメント追記のみ行う（部分成功を許容し、ジョブ全体を失敗させない）
- **認証情報**: GitHub Actions用にJIRA APIトークンをリポジトリ/組織シークレットとして別途発行する（対話セッションのAtlassian MCP認可とは別の資格情報）。本番JIRAプロジェクトでいきなり有効化せず、投稿内容を絞ったドライラン（特定チケットのみ等）で検証してから本適用する
- **仕様の置き場所**: この自動化は特定アプリに閉じずリポジトリ全体のCI/tooling（`.github/workflows/`）に関わるため、具体的なワークフロー実装は`apps/<app-name>/specs/`配下ではなく通常の`/requirement`フローの中でリポジトリ直下のタスクとして進める

## 影響

- `.claude/skills/pr/SKILL.md`のブランチ命名規約（`feature/<機能名>` → `feature/<JIRAキー>-<機能名>`）の更新が必要
- `.github/workflows/`にJIRA連携用ワークフローを新設する（未実装。具体化は別途`/requirement`で行う）
- JIRA APIトークン用のGitHub Actionsシークレットを新規発行する必要がある（誰が発行・管理するかは別途決める）
