# 開発フロー開始時のJIRAチケット確認

新しい機能・修正に着手する際(`/requirement`・`/fix`等の入口)の手順。プロジェクトによらず、このPCでの作業共通のルール。`~/.claude/CLAUDE.md`の「場面ごとに読む資料」から参照される詳細版。

- 対象のJIRAチケットが既にあるかユーザーに確認し、ある場合はチケットキー(例: `NMBM-123`)を確認して、以降のブランチ名(`feature/<チケットキー>-<機能名>`)に使う
- ない場合、以下のいずれかをユーザーに選んでもらう
  - **新規作成する**: `create-jira-ticket`スキル(`~/.claude/skills/create-jira-ticket/SKILL.md`)のフローでチケットを作成し、発行されたキーを使う
  - **チケット管理なしで進める**: ブランチ名にチケットキーを含めず(`feature/<機能名>`)進める
- プロジェクト固有の`requirement`/`fix`スキルはグローバル版を丸ごと上書きするため、そちらにも同じ確認手順を残しておく

GitHub Actions等によるJIRAチケットへのコメント・ステータス自動更新は、このルールとは別物で各リポジトリ固有の実装になる。
