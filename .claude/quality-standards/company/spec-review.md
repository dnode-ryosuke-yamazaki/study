# 会社標準 品質基準追加分 — spec-review

社内のAI駆動開発 標準テンプレート(`add-skeleton`)の `.claude/rules/development-process.md`・`documentation.md`、および `requirements` / `implement` / `test-design` スキルの手順から、仕様レビューの観点として効く項目を抜き出したもの。成果物の書式(フロントマター・REQ/DSN等のID体系・必須見出しの固定)に依存する規約はここには入れない(標準テンプレートを採用したリポジトリ側の `.claude/quality-standards/spec-review.md` に置く)。重要度基準・フィードバックテンプレートはbase層を継承する。

## 追加チェックリスト

### requirements.md
- [ ] 🟡 ヒアリングで決まらなかった事項が「未決事項」として、決定者と期限つきで残されているか(勝手に仮決めしていないか)
- [ ] 🟡 機能要件に優先度(Must / Should / Could 相当)が付いているか。付いていない場合、全件が同じ優先度で扱われる根拠があるか
- [ ] 🟡 振る舞いの記述に曖昧語(「適切に」「必要に応じて」「基本的に」)が使われていないか。テストで真偽を判定できる文になっているか

### design.md
- [ ] 🟡 APIを提供・改修する場合、エンドポイントごとの異常系(認証エラー・バリデーションエラー・境界値)が設計されているか
- [ ] 🟡 外部システムとファイル・メッセージで連携する場合、欠損・遅延・重複・フォーマット不正の各ケースの扱いが設計されているか
- [ ] 🔴 外部システム停止・タイムアウト・同時実行のいずれかが起こりうる機能で、その場合の振る舞いが設計に現れているか
- [ ] 🟡 非機能要件(性能・可用性・セキュリティ・運用)のそれぞれについて、検証方法と合格基準が決まっているか。機械的に検証できないものは実施方法が合意されているか

### 採番・トレーサビリティ
- [ ] 🟡 仕様項目の番号(`[n]`)を削除・再利用していないか。項目を廃止する場合は番号を残して「廃止」と明記しているか(テストの仕様コメント・他specからの参照が指す先を保つため)
